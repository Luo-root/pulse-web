# 性能

这一页回答两件事：**请求路径值多少**、**观测的钱花在哪**。数字来自本仓库的基准套件，每张表都带复现命令。

**版本**：pulse-web 的 `v0.2.0`（依赖 pulse v0.2.4）。**换默认出口、动请求路径、打 tag 时都重测这一节**，并且只比同轮配对出来的比值。

**本轮**：2026-09-22 · i9-14900HX / 32 逻辑核 / Go 1.27 / Windows amd64 · **插电**。

## 怎么读这一页

数字分两类，读法完全不同：

- **确定性的一类**：`allocs/op` 与 `B/op`。它们已经固化成 CI 断言（`bench/budget_test.go`），**跨轮、跨机器都稳定**。
- **浮动的一类**：`ns/op`。同一格换一次会话就能漂 2–4×，所以**只在本轮内可比**，不能跟别的轮次、别的机器比。

为了让「本轮」可辨识，下面每张表都带一条**与框架无关的对照行**（stdlib ServeMux，纯标准库）。对照行变了说明机器状态变了，**没有同轮对照行的 ns 不要引用**。

要绝对值就在安静机器上按下面的命令自己跑一轮，并与**同一轮**的对照行比。

> 这台机器还有一条更硬的限制：`time.Now()` 的推进量子实测约 **0.3 ms**（连续采 200 万次只有 34 个不同的非零 delta）——短于这一档的区间会被读成 0 或量化值。ns 在这里连「精确到微秒」都谈不上。测法与原始数据见[设计文档](https://github.com/Luo-root/pulse-web/blob/main/docs/design/web-framework-design.md)的实测数据一节。

## 请求路径的成本分解

口径 `-benchtime=20000x -count=5` 取中位，同轮同口径。**凡要相减得出 Δ 的，必须取本表内的两行。**

> `Engine` 各档的 B/op 含 **16 字节**的 `Ctx` 字段（存 span 身份，2026-09-17 · [#76](https://github.com/Luo-root/pulse-web/issues/76)）：`Ctx` 定长，所以不装 span 出口的宿主同样付它。**分配计数逐档不变**；上表的 ns 列仍是加字段之前那一轮（ns 不设门禁，跨轮会比；分配计数与 B/op 才是确定性判据）。

| 场景 | ns/op | allocs | B/op |
|---|---|---|---|
| stdlib ServeMux 路由匹配（**对照行**，与框架无关） | 198 | 5 | 224 |
| scope 派生 + 销毁（`Derive + Dispose` 基线） | 81 | **2** | 192 |
| + 裸作用域局部绑定 | 327 | 14 | 649 |
| + `observability.AttachCollector` | 342 | 14 | 681 |
| 同上 · 10 / 50 / 100 插件树 | 345 / 361 / 370 | 14 | 681 |
| 同上 · 50 插件并行 | 566 | 14 | 681 |
| `Engine` 请求路径（`New()`，0 / 10 / 50 插件） | 1774 / 1819 / 1937 | 22 | 6314 |
| `Engine` 请求路径 + `WithCollector()` | 2123 | **34** | 6803 |
| `Engine` 请求路径（`Minimal()`） | 1443 | 17 | 5858 |
| `Engine` 请求路径 + `BodyLimit` 路由 | 1877 | **23** | 6379 |
| `Engine` 请求路径 + `c.JSON` | 见下 | **25** | 6453 |

由表内两行推出的 Δ（同轮，可相减）：

- **`WithCollector()` 的每请求成本** = 2123 − 1774 = **+349 ns / +12 allocs**（端到端）
- **`Minimal()` 省下的** = 1774 − 1443 = **−331 ns / −5 allocs**（关掉 Trace / AccessLog / Sink）
- **`BodyLimit` 的每请求成本** = 1877 − 1774 = **+103 ns / +1 alloc**——多出来的分配就是 `http.MaxBytesReader` 返回的包装器本身（绑在请求上，无法复用），ns 那 103 仍然落在噪声里（同档 5 次落在 1839–2177）。
- **经 `Adapt` 接一层生态中间件的每请求成本** = **+5 allocs / +152 B**（22 → 27、6314 → 6466，**确定性判据**，由分配门禁的 `default+adapt` 档钉住）。拆解见设计文档表 B：适配层本身 4 次（`adaptProxy` + 内层闭包 + 它捕获的 `called` / `err` 两次装箱）+ 中间件自身那层 1 次；其中两次装箱**是可以省的**，本轮只记账不动实现。
- **装配规模与请求路径无关**：`Engine` 请求路径在 0 / 10 / 50 插件下是 1774 / 1819 / 1937 ns、**allocs 恒为 22、B/op 恒为 6314**；kernel 层 10 / 50 / 100 插件树 **allocs 恒为 14**。插件树大小不改变每请求成本——这正是装配能力能成立的前提。
- **包含关系自检（防倒挂）**：`AttachCollector` = 裸绑定 + 1 个 Collector 结构，判据看 **B/op**（681 > 649）。两者 allocs 同为 14；本轮 ns 同向（342 > 327）但只差 4%，仍在噪声带内——**别拿 ns 下这个结论**。
- **`c.JSON` 先编码到 buffer**：每响应 **+2 allocs**（22 → 25，确定性判据，由分配门禁覆盖），换来「编码失败不再发 200 空体」。表中 B/op 6453 取自设计文档表 B 的**同轮探针**（6341 → 6453，即 +112 B）——它与本表 `Engine` 行的 6314 不是同一轮，**不要相减**。ns 请自己在同轮里跑对照。

复现：

```bash
# 对照行 + kernel 层
go test -run '^$' -bench 'BenchmarkStdlibServeMux_Route|BenchmarkScopeCycle|BenchmarkRequestCycle' -benchtime=20000x -count=5 ./bench/

# Engine 请求路径（default / collector / minimal / body-limit）
go test -run '^$' -bench 'BenchmarkEngineRequestPath' -benchtime=20000x -count=5 ./bench/

# 分配门禁：把上表的 allocs / B/op 固化成断言（必须不带 -race 跑）
go test -run TestRequestPathAllocBudget ./bench/
```

## 出口（Sink）值多少

出口是观测成本的所在（机制见[观测](/guide/observability)）——**出口有多慢，请求路径就有多慢**。

同一个 `Record`、出口都写 `io.Discard`（保留格式化与锁的成本，排除终端/磁盘 I/O）：

| 出口 | ns/op | allocs | B/op |
|---|---|---|---|
| `web.ConsoleSink`（**默认出口**） | 235 | **0** | **0** |
| `observability.LineSink`（上游行式） | 274 | **0** | **0** |
| `observability.SlogSink`（结构化） | 1398 | **18** | 1127 |

端到端（同一条请求路径，只换出口）：默认出口 **2471 ns** vs nop 出口 **2240 ns** = **每请求 +0.23 µs、+0 allocs**。这一格噪声偏大（nop 档 5 次落在 2131–2920），所以又独立复跑了一轮：2628 vs 2433 = **+0.20 µs**，同向。

两点要读出来：默认出口**零分配**（渲染在 `LineSink` 的临界区内单缓冲完成）；而 `SlogSink` 每条要 18 次分配、贵 5 倍——它本来就是**给机器读**的那条路，代价与用途都在这里。

复现：

```bash
go test -run '^$' -bench 'BenchmarkSinkWrite_ConsoleVsUpstream|BenchmarkRequestPath_DefaultSink' -benchmem -count=5 ./bench/
```

出口怎么选见[观测](/guide/observability)；要吞吐就把慢出口包进 `observability.NewAsyncSink`。

## 与 gin 的真实负载对比（2026-09-22，插电）

这一节回答「**与 gin 同级吗**」。采集工程是仓库里的 `loadtest/`——**独立 module**，带 gin 依赖（核心模块零第三方依赖，不为「跟 gin 比一次」破例）；这里只留口径与结论。

口径：两侧独立进程、共用同一份 `http.ListenAndServe` bootstrap、**只让 handler 是变量**；同一格内两侧相邻跑、奇偶轮交换先后、**只用偶数轮**；每格取 RPS 中位那一轮的整套分位，两侧比值取**逐轮配对比值的中位**。压测器自写（固定并发、连接全复用、计时窗口内每个请求都进分位，不采样）。机器：i9-14900HX / 32 逻辑核 / `GOMAXPROCS=32` / Go 1.27 / Windows amd64，**插电**。两侧的日志出口都指向空设备——保留每请求的格式化成本，排除终端 / 管道 I/O。

| 档位 | 并发 | pulse-web RPS | gin RPS | pulse/gin | pulse p99 | gin p99 |
|---|---|---|---|---|---|---|
| `bare` | 64 | 55579 | 59296 | **0.94x** | 4.89ms | 4.81ms |
| `bare` | 256 | 57919 | 59258 | **0.98x** | 20.03ms | 24.43ms |
| `obs` | 64 | 51841 | 58060 | **0.90x** | 4.96ms | 5.02ms |
| `obs` | 256 | 58336 | 59406 | **0.99x** | 19.20ms | 24.54ms |

- **裸档同级**：0.94–0.98×；c=256 的 p99 更低（20.03ms vs 24.43ms），c=64 两侧持平（4.89ms vs 4.81ms）。对拍档是 `gin.New()` ↔ `web.New(web.Minimal())`——两侧都没有默认中间件。
- **观测档**（`gin.Default()` ↔ `web.New()`，两侧都开默认中间件）：0.90× / 0.99×。pulse-web 这一档比 gin 多做三件事——TraceID、路由模板（`/users/{id}` 而不是实际路径）、错误分类；作为参照，gin 自己的默认中间件在这两档之间的代价是 4.6% / 2.8%。
- **口径的效力在「配对」上，不在绝对值上**：同一格换一次会话能从 28k 变到 78k（上一轮 2026-09-20 的绝对 RPS 只有本轮的一半左右，纯属机器状态），所以只认同轮配对比值（供电状态这类整机漂移被配对抵消）。**早先两次独立会话的配对比值逐项吻合**（0.90/0.91、0.95/0.95、0.81/0.82、0.92/0.93）——这才是它比绝对值可信的地方。
- 更早那轮（2026-09-14）观测档是 **0.65× / 0.88×**——它用的是**当时的**默认出口 `SlogSink`；默认换成 `ConsoleSink` 当轮（2026-09-16）按同一口径重采是 0.82× / 0.93×，此后各轮在波动带内缓慢上移到本轮的 0.90× / 0.99×。绝对值跨轮不可比，这里只比同轮配对出来的比值。
- 2026-09-20 那轮重跑过两次，当时登的是后一次：先因**放开响应写出器的 `Hijack`**（动了请求路径上的 writer）按同一口径重采（0.90× / 0.94×、0.87× / 0.92×），随后评审修复 hijack 之后的写保护又复跑一轮复核（0.89× / 0.95×、0.85× / 0.91×）——两次落在同一波动带，**结论未变**。2026-09-21 又因 `Adapt` 的回填修复（同样在请求路径上）复跑一轮（0.90× / 0.93×、0.86× / 0.93×）；**2026-09-22 随 v0.2.0 发版按同一口径重采**，登的就是上面这张表（0.94× / 0.98×、0.90× / 0.99×）。每一轮都落在同一波动带内。
- 采集工程以前待在侧分支上，结果默认出口换代之后它**静默地继续量旧默认**——不报错、不告警。现在它跟着主干走，由 CI 单独覆盖它的 build / vet / test 防腐烂。

复现：

```bash
cd loadtest
go run ./cmd/compare -probe -passes 4 -d 8s -warmup 2s           # 记录进文档的那次
```

`loadtest` 的 `replace` 指向仓库根，所以比的是**当前工作副本**；CI 只跑它的 build / vet / test，**不跑压测与基准**——CI 上的计时是噪声。
